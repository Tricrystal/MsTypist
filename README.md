# MsTypist — Word 文档批量生成工具

*A Java tool fill .docx with .xlsx just like a typing lady.*

读取一个 Excel 数据表和一组 Word 模板（`.docx`），把表格中**每一行数据**按模板批量生成对应的 Word 文档：文档正文、表格、页眉页脚以及**文件名**中的占位符都会被该行对应列的值替换，并按指定的"标识列"分文件夹输出。

> 典型场景：给一批店铺/客户，每人生成一套起诉状、授权委托书、证据清单等法律文书；或给一批员工生成通知书、证书等。

提供两种使用方式：**图形界面版**（推荐，单窗口免输入命令）和**命令行版**。程序为单个 fat jar，字节码目标 Java 8，兼容 **Windows XP ~ Windows 11**（XP 需已安装 JRE 8；Win7 及以上可用自带 JDK）。

## 快速开始（图形界面版，推荐）

1. 双击 **`0.31/run-gui.cmd`**，出现单窗口界面；
2. 依次选择：**模板文件**（可按住 Ctrl 多选多个 `.docx`）、**Excel 数据表**（`.xlsx`）、**输出目录**；
3. 在"目录命名列(标识列)"下拉框中选择用哪一列的值命名输出子文件夹（选中 Excel 后自动加载所有列名）；
4. 点击 **【检查模板】**，下方文本框会列出每个模板中占位符与 Excel 列名的对照（`√ {{被告}} = Excel列[被告]`），缺失的列名会标 ×，并汇总列出未被模板引用的 Excel 列；
5. 确认无误后点击 **【开始执行】**，下方文本框实时输出每行的生成结果和报错，结束显示统计（成功/失败/跳过）与输出目录。

窗口为单个界面，无页签切换。执行在后台线程进行，界面不会卡死；单个模板失败不会中断整批，会逐个记录错误并继续。

> 排障：双击 `run-gui.cmd` 如有异常，错误信息会停留在控制台（脚本对启动失败自动暂停），按提示处理即可。常见问题：`MsTypist-gui.jar` 与脚本不在同一文件夹；XP 未安装 JRE 8；PATH 上的 Java 版本低于 8（此时可改用 `jdk-15.0.2` 里的 java 手动启动）。

## 快速开始（命令行版）

1. 进入 `0.31` 目录，把准备好的 `data.xlsx` 和模板 `.docx` 放进 `input/` 文件夹；
2. 双击 **`run.cmd`**（等价于命令行执行 `.\jdk-15.0.2\bin\java.exe -jar -Xmx512m -Xms512m .\MsTypist-cli.jar`）；
3. 程序启动后，按提示**输入标识列名**（该列的值将作为输出子文件夹的名字，中间不能有空格），回车；
4. 等待控制台打印 `end`，到 `output/` 下查看结果。

`input/` 中自带的示例文件可以直接体验（GUI 版选择 `input/` 里的文件即可；命令行版双击运行后输入 `文件夹`），即可看到 `老人与海/`、`挪威的森林/` 等文件夹和生成好的示例文档。

## 使用步骤

### 第 1 步：准备 Excel 数据表

- 后缀必须为 `.xlsx`，放入 `input/` 文件夹（多个 Excel 时**只读取第一个**）；
- 程序会遍历**所有工作表**；
- 每个表的**第一行是表头**，每个表头名即一个字段名；从第二行起，每行是一条数据；
- 表头与模板中的占位符一一对应，例如表头 `被告`、`原告名`、`店铺名`。

### 第 2 步：准备 Word 模板

- 后缀必须为 `.docx`（`.doc` 老格式会被忽略，请先在 Word 中另存为 `.docx`），放入 `input/` 文件夹；
- 把需要替换的位置写成 `{{字段名}}`，字段名与 Excel 表头完全一致，例如：

  > 委托人姓名：`{{原告名}}`　被告：`{{被告}}`

- 模板**文件名**里也可以使用占位符，如 `起诉状（{{店铺名}}）.docx`；
- 没有任何占位符的模板也会被处理，相当于原样复制到各个输出文件夹。

### 第 3 步：运行并输入标识列名

程序会提示：

> 请输入标识列名（将作为输出目录名，中间不允许存在空格）：

输入 Excel 中某一列的表头名（如 `店铺名`），每行数据将输出到 `output/<该行的店铺名>/` 下。

### 第 4 步：查看输出

```text
output/
├── 老人与海/
│   ├── test file.docx                     ← 无占位符的模板，原样复制
│   ├── sample1 老人与海.docx               ← 文件名中的 {{文件夹}} 已替换
│   ├── sample2 飞机.docx                   ← 文件名中的 {{标志B}} 已替换
│   └── sample3 船.docx
├── 挪威的森林/
│   └── ……
└── 黄金时代/
    └── ……
```

以上即 `input/` 示例数据（表头：`序号 / 文件夹 / 占位符1 / 标志B / 替换丙 / 列IV / 字段肆 / 原告名`）运行后的实际结果。

## 占位符规则

| 位置 | 语法 | 行为 |
|---|---|---|
| 文档正文、表格（含嵌套）、页眉、页脚 | `{{字段名}}` | 替换为该行该列的文本值 |
| 模板文件名 | `{{字段名}}` | 替换为该行该列的文本值 |
| 对应单元格为空 | — | 占位符被**直接删除**（文件名中同样删除） |

- 占位符支持跨段内多个 run 断裂的情况（中文输入法下 Word 常把一个词拆成多段，程序底层用 poi-tl 模板引擎处理，不受影响）；
- 字段名区分大小写，且必须与表头完全一致；
- 替换后的文本继承占位符所在位置的样式。

## 实现原理

```
模板 *.docx（可多选） ┐
                      ├→ 逐行渲染（poi-tl）→ 输出目录/<标识列值>/<替换后文件名>.docx
Excel *.xlsx（首行=表头） ┘
```

1. **读取**：GUI 版在界面中选择模板与 Excel；命令行版扫描 `input/` 下所有 `.docx` 并取第一个 `.xlsx`。遍历所有工作表，首行作表头，其余每行转成 `Map<字段名, 单元格文本>`（各行保持原有顺序，存入 `List`）。
2. **标识列**：GUI 版用下拉框选择；命令行版启动后由控制台输入。标识列为空的行跳过并提示原因。
3. **渲染**：对每行数据，先按标识列的值创建输出子文件夹；对每个模板调用 poi-tl 的 `XWPFTemplate.compile(模板).render(行数据)` 完成正文/表格/页眉页脚替换，输出为"文件名占位符替换后"的新文件。
4. **结束**：GUI 版在文本框输出统计；命令行版打印 `end`。

技术栈与依赖版本：

| | GUI 版（MsTypist-gui.jar） | 命令行版（MsTypist-cli.jar） |
|---|---|---|
| Word 模板引擎 | [poi-tl 1.12.2](https://deepoove.com/poi-tl/)（2023，已更新） | poi-tl 1.9.1（2021） |
| Apache POI | 5.2.2（2022，随 poi-tl 引入，已更新） | POI 4.1.2（2021） |
| Java 要求 | 字节码 Java 8，JRE 8 ~ 21+ 均可运行 | 打包时按 Java 15 构建 |
| 单元格读取 | `DataFormatter` 按显示格式读取（`1` 不会变成 `1.0`，日期保持显示格式） | `toString()` 原始值 |

构建：在仓库根目录执行 `mvn package`（需 JDK 8+ 与网络），产物为 `target/MsTypist-gui.jar`；`pom.xml` 中通过 maven-compiler-plugin 指定 `--release 8` 保证兼容旧系统。

## 注意事项

1. **系统兼容**：GUI 版可在 Windows XP ~ Windows 11 运行，但 **XP 必须已安装 JRE 8（32 位）**——自带的 `jdk-15.0.2` 不支持 XP（`run-gui.cmd` 会优先使用系统安装的 Java，没有才退回自带 JDK）；Win7 及以上开箱即用。
2. **只认 `.docx` 和 `.xlsx`**：`.doc` / `.xls` 会被忽略；命令行版 `input/` 中多个 `.xlsx` 时只读第一个（按文件名排序），多余的请移走。
3. **标识列要求**：该列各行最好非空且互不相同——为空的行会被跳过；两行标识列值相同会写入同一文件夹，同名文件**后处理的行会覆盖先处理的行**。
4. **数字与日期格式**：GUI 版按单元格显示格式读取（`1` 就是 `1`，日期保持显示格式）；命令行版按原始值读取，数值列会变成 `1.0` 这样的形式，用于替换或命名前请在 Excel 中先转为文本。
5. **空单元格即删除**：某行为空时，模板中对应 `{{字段}}` 会被删除而不是保留，如需保留默认值请把数据补全（选中 Excel 后可先用【检查模板】核对）。
6. **单文件容错**：GUI 版中单个模板失败只记录错误并继续；命令行版某个模板损坏会中断整个批次，需修复或移除问题文件后重跑。
7. **必须在程序目录启动（命令行版）**：输入输出目录按运行目录（`user.dir`）解析，双击 `run.cmd` 已保证；命令行手动运行请先 `cd` 到 `0.31` 目录。GUI 版用文件对话框选择路径，无此限制。
8. **清理临时文件（命令行版）**：Word 打开模板时产生的 `~$xxx.docx` 临时文件如残留在 `input/` 中，也可能被当作模板处理，请删除。
9. 开发者注意：在 Git Bash 等终端用管道给命令行版传标识列名时需按 **GBK** 编码传中文（Windows 控制台交互输入无此问题）。

## 源码版本说明（重要）

`src/` 下有两套实现，历史沿革如下：

1. **`GuiApp.java`（图形界面版，当前最新）**：Swing 单窗口界面，基于 poi-tl 1.12.2；由仓库根目录的 `pom.xml` 构建，产物为 `MsTypist-gui.jar`。这是唯一"源码与 jar 同步"的版本。
2. **`MsTypist-cli.jar`（命令行版，2021-05-19 构建）**：基于 poi-tl 1.9.1，`{{字段名}}` 占位符、运行时输入标识列名。
3. **`App.java`（旧源码，仅作参考）**：更早的一个实现——`$字段名$` 占位符（手写正则逐段替换，另有 `${字段名}` 匹配器残留未使用）、硬编码 `店铺名` 作目录列、`HashSet` 存行（乱序且整行重复时被去重）。**与命令行 jar 行为不一致**，直接修改它不会影响任何 jar 的行为，`pom.xml` 中已将其排除编译。

| | GUI 版（GuiApp → MsTypist-gui.jar） | 命令行版（MsTypist-cli.jar） | App.java（旧源码，未用于构建） |
|---|---|---|---|
| 占位符 | `{{字段名}}`（poi-tl 渲染） | `{{字段名}}`（poi-tl 渲染） | `$字段名$`（手写正则） |
| 输出目录列 | 下拉框选择标识列 | 运行时控制台输入 | 硬编码 `店铺名` |
| 数据存放 | `List`，保持行序，空标识列跳过 | `List`，保持行序，空标识列跳过 | `HashSet`，乱序去重 |
| 单元格读取 | `DataFormatter` 显示格式 | `toString()` 原始值 | `toString()` 原始值 |
| 单文件容错 | 失败记录并继续 | 失败中断整批 | 失败中断整批 |

重新构建 GUI 版：在仓库根目录执行 `mvn package`（需 JDK 8+，会从 Maven Central 拉取依赖），把 `target/MsTypist-gui.jar` 复制到 `0.31/` 即可。修改 GUI 功能请编辑 `GuiApp.java` 后重新构建，源码与产物保持同步。
